## Important — fix before push

### Money / flags / grouping (domain logic)

1. **A receipt claimed by rows is also flagged "supports no row".**
   `backend/app/claims/checks.py:305-320, 331-349` (DUPLICATE_RECEIPT /
   RECEIPT_AMBIGUOUS) never add the receipt to `matches`; `:410-425`
   (UNCLAIMED_RECEIPT) keys only on `id not in matches`. Verified: two rows + one
   150.00 receipt → DUPLICATE on both rows **and** an open UNCLAIMED on the same
   receipt; the receipt also lands in `unused_evidence` (`listing.py:346`). The
   reviewer decides the same receipt twice with contradictory prompts. Fix:
   collect ids referenced by duplicate/ambiguous verdicts and exclude them from
   UNCLAIMED.

2. **Foreign-currency derived lines are summed as MYR.** `listing.py:465-471`
   `_money` returns `total or amount` with no currency check; derived rows from
   non-MYR receipts have `total=None` (`worker.py:522`) so USD 50 adds 50.00 to
   the MYR payment row and `rows_total`. Only CURRENCY_MISMATCH (dismissable with
   a note) stands in the way. Fix: when `currency != "MYR"` and `total is None`,
   exclude the line and name it in `not_included` until a rate/total exists.

3. **Prefix elimination masks a real ownership conflict.** `grouping.py:96-100`
   removes *both* sides of a substring pair. Verified: `Aegene Ong`,
   `Aegene Ong Li`, `Nick Goh` in one case → no OWNERSHIP_CONFLICT (two names
   alone → conflict). Fix: cluster names by the substring relation (union-find)
   and conflict when clusters > 1.

4. **Document titles become STRONG name signals.** `grouping.py:27,46-49`
   `_NAME_PREFIX` turns `Expense Report_July.pdf` → "Expense Report",
   `Claim Form_ER(...).xlsx` → "Claim Form" — a folder with one real name file
   then shows a false OWNERSHIP_CONFLICT and shuts the grouping gate. Fix: demote
   file-name-prefix names to weak unless they match a header/ER-code name, or
   stop-list document words.

5. **An extra receipt seen only by the second read is dropped while the note
   says it was added.** `evidence.py:384-396` — `seen` already holds every
   position from read 1, so an extra at a seen position hits `continue`.
   Verified: read 1 = 1 receipt, read 2 = 2 receipts → output 1 receipt + note
   "extra one(s) were added as low-confidence". Fix: append every remaining
   `by_pos_b` entry with the "only one read saw this" note; drop the position test.

6. **Unbounded row span from model output.** `report_reader.py:85` `last_row`
   has no upper bound; `:309` / `:383-392` iterate `range(first_row, last_row+1)`
   with cell-creating `ws[...]` access on a non-read-only workbook. Verified:
   `last_row=200000` on a 1-row sheet → 2.2 s / 97 MB / 400k cells; `10**9`
   wedges the worker before any audit runs. Fix: clamp to `ws.max_row`, `le=` on
   the fields, reject spans wider than `MAX_SHEET_ROWS` before extracting.

### AI loop / tools / sandbox

7. **Unverified claimant names ship as proposed Claimants when the case key
   contains ":" or starts with "case ".** `investigator/investigator.py:212`
   reverse-parses prose problem strings (`p.split(":")[0].replace("case ", "")`);
   `:244 verified = c.key not in unverifiable`. Verified: keys `"case 1"`,
   `"c:1"` → `verified=True` for a name the audit could not find anywhere —
   contradicts THREAT-MODEL §2. Key is model-chosen (any text ≤40). Not fixed in
   WT. Fix: `audit_proposal` returns structured problems (set of unverified
   keys / tuples), never parsed prose.

8. **Cancel does not stop the investigator's model loop; at HEAD a cancelled
   run is resurrected to `map_ready`.** `investigator.py:150-172` checks only
   wall time; `cancel_run` only flips the harness; `runner.py:150,176` then
   writes `map_ready` over `failed` (cancel allowed during `surveying`/`mapping`,
   `routes.py:291-299`). Resurrection **fixed in WT** (`_advance` conditional
   UPDATE + `RunCancelled`); model spend after cancel is not. Fix: expose
   `cancelled` on `InvestigationTools`, check before each round, break.

9. **Cancel does not stop a worker already inside `_work`.** `worker.py:322`
   is the only status check; `_work` (`:402-680`) runs up to 200 pages, tie-breaks
   and the category judge with no re-check, then commits rows onto a `failed`
   run (`:680`). Up to POOL_SIZE × WORKER_REQUEST_CAP AI calls after cancel. Fix:
   re-read `run.status` in `budget()` / between stages and raise into the existing
   discard path.

10. **Sandbox (HEAD) buffers unbounded child output into the FastAPI process
    before the caps; no RLIMIT_FSIZE; symlinks in `out/` are followed.**
    `tools/sandbox.py:171,179,187-192,237-255`. Memory/FSIZE/stream caps
    **fixed in WT**; symlink following is NOT (`p.is_file()`/`p.stat()` still
    follow → the host hashes an arbitrary readable file and returns the sha256
    to the model). Fix: skip `p.is_symlink()` / `O_NOFOLLOW`, refuse the run on
    any symlink or dir-escape in `out/`.

11. **Path redaction misses Windows single-backslash paths and every non-
    /Users,/home absolute path.** `tools/harness.py:87` raw-string regex matches
    two literal backslashes. Verified: `C:\Users\bob\...\x.xlsx`,
    `/var/app/.../y.pdf`, `/tmp/claims-sbx-.../z` pass through to model context,
    `ToolExecution.note`, replay bundle and TOOL_FAILED flag text. Fix:
    `r"[A-Za-z]:\\[^\s'\"]+"` + a generic POSIX absolute-path pattern; redact
    `tempfile.gettempdir()` and `DATA_DIR`.

12. **`render_page` rasterises every page of the PDF per single-page request.**
    `tools/documents.py:85` → `evidence.render_page` → `pipeline/images.py:22
    document_to_pngs` (all pages, 150 dpi). Same path behind `GET .../file`
    (`routes.py:463`), which also 500s on `.docx/.txt/.msg` (only IndexError
    caught, `:464`). 200-page bundle × 400 tool calls = 80k page renders. Fix:
    render only the requested page (pymupdf `pdf[page-1].get_pixmap`), map
    ValueError → 415/404.

### HTTP / orchestration

13. **WT regression — `start_background()` from a sync route raises at
    runtime.** `runner.py:289-291` uses `asyncio.get_event_loop().create_task`.
    WT `set_artifact_disposition` (`routes.py:879`, plain `def` → threadpool)
    calls it at `:902`; on Python 3.12 in a worker thread this is
    `RuntimeError: There is no current event loop`. The disposition is already
    committed → 500 to the client, employee stuck `pending` on a `ready` run, no
    retry, and `output_blockers` does not name it. The new test passes only
    because `tests/test_claims_baseline.py:52` stubs `start_background`. Fix:
    capture the loop at startup and use `asyncio.run_coroutine_threadsafe` /
    `loop.call_soon_threadsafe`; keep task references; add a done-callback that
    logs and fails the run; un-stub it in at least one HTTP test.

14. **Optimistic concurrency is read-compare-write, not compare-and-set.**
    `routes.py:482-497` compares `expected_revision` in memory; `cases.py:25-27`
    does `run.revision += 1`; the UPDATE has no `AND revision=?`. Case routes are
    sync and run concurrently in the threadpool, so two requests with the same
    revision can both pass and both commit; second silently wins. The threat
    model (§5) presents this as the "two reviewers" control. Fix: conditional
    UPDATE (`WHERE id=? AND revision=?` → 409 on 0 rows) — the same pattern WT
    just added for status in `runner._advance` — or `BEGIN IMMEDIATE`.

15. **Background task failures are unobserved.** `runner.start_background`
    keeps no reference and no done-callback; `worker.retry_employee`
    (`:770-786`) has no try/except, so a retry that throws after flipping to
    `verifying` (`:777`) leaves the run `verifying` until the next restart.
    Fix: done-callback → `_fail(run_id, ...)`; wrap `retry_employee` like the
    other entry points.

16. **Request bodies are untyped `dict`s → 500s instead of 4xx.** Every
    mutation takes `body: dict`; `confirm_map` (`routes.py:346-348`) only checks
    `employees` is a list, then `mapping.py:421,437-441` / `routes.py:423-436`
    index `e["folder"]`, `fr["path"]` → TypeError/KeyError. `update_claims_settings`
    is ~115 lines of hand validation (`:1125-1237`). Fix: Pydantic models per
    route (422 with field paths for free); move profile validation into
    `profile.py`.

## Done well
- Server-side output gate (`output_blockers`) recomputed from state on every
  read; the screen cannot bypass it; tests pin it end to end.
- Money is Decimal and cent-quantised through reader → checks → listing;
  "at or above" and `0` as a real setting are deliberate and tested; TSV output
  hardened against formula injection.
- AI answers are structural and code-audited (coordinates demanded, arithmetic/
  span/total verified, paths and ER codes must exist in the survey); the
  adapter can never mint a confirmed Claimant; tools are manifest-id-only with
  a containment check; calculator is an AST allowlist; `run_python` absent
  unless three switches agree; cleared env, no shell, double-run hash compare.
- Restart safety: resting vs in-progress statuses, `fail_interrupted_runs`,
  WAL + busy_timeout, versioned idempotent migrations with a real
  pre-migration-DB test; worker isolates one employee's failure.
- Frontend: typed `StaleRunError`, `expected_revision` on essentially every
  mutation, sequence-counter reload, polling cleaned up on unmount, no
  `dangerouslySetInnerHTML`/eval/localStorage, shared components extracted.
